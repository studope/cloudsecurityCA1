# ZAP Vulnerability Remediation Report

**Target:** `https://store.opechimil.online` (WordPress + WooCommerce, Astra theme, Elementor, Apache on Amazon Linux, fronted by an AWS ALB)
**Scanner:** OWASP ZAP 2.17.0 (by Checkmarx)
**Source scans:** `P0-zap-scan.html`, `P1-zap-scan.html`
**Scope of this report:** Only the ZAP-reported vulnerabilities that were **remediated**. Findings with no fix yet (e.g. Swiper CVE-2026-27212, Anti-CSRF tokens, SRI) are excluded.

## Detailed remediation

### 1. SQL Injection  *(High)*
**What ZAP found:** Boolean-based SQL injection on `POST /my-account-2/` (payloads `... AND 1=1 --` / `... AND 1=2 --` altered the response, with data returned).
**Root cause:** The `/my-account-2/` account/checkout flow is generated by the **CartFlows** plugin, which was on a vulnerable version (3.1.2).
**Fix applied:**
```bash
sudo -u apache wp plugin update cartflows --path=/var/www/html   # 3.1.2 -> 3.1.3
```
All other plugins, WordPress core, and the Astra theme were also confirmed up to date. Wordfence WAF remains active as a compensating control.
**Status:** Patched. Requires an authenticated re-scan / manual re-test of `POST /my-account-2/` to confirm closure.

### 2–7. HTTP security-header findings *(Medium/Low)*
All fixed centrally in a single Apache config file: **`/etc/httpd/conf.d/security-hardening.conf`** (source kept in `apache/security-hardening.conf`). Apache is the enforcement point so every response — pages, static files, admin — receives the headers.

**Directives added:**
```apache
ServerTokens Prod
ServerSignature Off

<IfModule mod_headers.c>
    Header always set X-Frame-Options "SAMEORIGIN"
    Header always set X-Content-Type-Options "nosniff"
    Header always set Strict-Transport-Security "max-age=31536000"
    Header always set Referrer-Policy "strict-origin-when-cross-origin"
    Header always set Content-Security-Policy "default-src 'self'; img-src 'self' data: https:; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; frame-ancestors 'self'; object-src 'none'; base-uri 'self'; upgrade-insecure-requests"
    Header always unset Access-Control-Allow-Origin
</IfModule>
```

| Finding | Directive that fixes it | Purpose |
|---------|------------------------|---------|
| Missing Anti-clickjacking Header | `X-Frame-Options: SAMEORIGIN` + CSP `frame-ancestors 'self'` | Prevents the site being framed (clickjacking) |
| CSP Header Not Set | `Content-Security-Policy` | Restricts where scripts/styles/objects may load from (XSS defence) |
| Cross-Domain Misconfiguration | `Header unset Access-Control-Allow-Origin` | Removes the over-permissive `*` CORS header |
| Strict-Transport-Security Not Set | `Strict-Transport-Security: max-age=31536000` | Forces browsers to use HTTPS only for the host |
| X-Content-Type-Options Missing | `X-Content-Type-Options: nosniff` | Stops MIME-type sniffing |
| Server Leaks Version Information | `ServerTokens Prod` / `ServerSignature Off` | Hides the Apache version string |

**Notes:**
- **HSTS** is sent unconditionally because TLS is terminated at the ALB (origin sees HTTP, so `%{HTTPS}` is off). `includeSubDomains` was intentionally omitted so the policy applies to `store.opechimil.online` only, not the apex or sibling subdomains.
- **CSP** retains `'unsafe-inline'` for `script-src`/`style-src` because Astra/Elementor inject inline assets. This clears the *CSP Header Not Set* finding; tightening to nonces/hashes is a documented future step.

**Verification (`curl -sI https://store.opechimil.online/`):**
```
server: Apache
x-frame-options: SAMEORIGIN
x-content-type-options: nosniff
strict-transport-security: max-age=31536000
referrer-policy: strict-origin-when-cross-origin
content-security-policy: default-src 'self'; img-src 'self' data: https:; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; frame-ancestors 'self'; object-src 'none'; base-uri 'self'; upgrade-insecure-requests
```
`access-control-allow-origin` no longer present. Server version string removed.

### 8–10. Cookie security-flag findings *(Low)*
**What ZAP found:** Cookies set without `HttpOnly`, `Secure`, and `SameSite` attributes.
**Root cause:** Behind the ALB, WordPress's `is_ssl()` returned false (origin receives HTTP), so WP/WooCommerce cookies were issued without the `Secure` flag.
**Fix applied — two layers:**

1. **WordPress-level (root cause)** — `wp-config.php` trusts the ALB's forwarded protocol so WP knows it is on HTTPS and sets `Secure` natively:
   ```php
   if ( isset($_SERVER['HTTP_X_FORWARDED_PROTO']) && $_SERVER['HTTP_X_FORWARDED_PROTO'] === 'https' ) {
       $_SERVER['HTTPS'] = 'on';
   }
   ```
2. **Apache-level (backstop, covers all cookies incl. `SameSite`)** — in `security-hardening.conf`:
   ```apache
   Header edit Set-Cookie ^(.*)$ "$1; HttpOnly; Secure; SameSite=Lax"
   ```
   (`always` deliberately omitted — application cookies live in `headers_out`, which `Header edit` targets.)

**Status:** Applied. Cookies could not be observed via `curl` because anonymous pages are cached and login is federated to AWS Cognito (no cookie on those responses). To be confirmed on the ZAP re-scan, which exercises the WooCommerce cart/checkout flows that set cookies.

## Additional hardening applied (defence-in-depth)
These accompanied the fixes above (some map to wpscan findings rather than ZAP):

| Action | Config | Purpose |
|--------|--------|---------|
| Disable directory listing | `Options -Indexes` | `/wp-content/uploads/` no longer browsable (returns 403) |
| Block version-disclosure files | `<Files readme.html/license.txt>` deny | Hides WordPress version |
| Disable XML-RPC | `<Files xmlrpc.php>` deny | Removes brute-force/DoS amplification endpoint |
| Block PHP execution in uploads | `<FilesMatch \.php$>` deny in uploads | Defence against upload-to-RCE |
| Remove dashboard code editor | `define('DISALLOW_FILE_EDIT', true);` | Prevents backdoor injection via a compromised admin |
| Disable traffic-driven WP-Cron | `define('DISABLE_WP_CRON', true);` + system cron every 15 min | Removes public `wp-cron.php` DoS vector while keeping scheduled tasks reliable |

**Verification:**
```
GET /wp-content/uploads/  -> 403
GET /readme.html          -> 403
```
